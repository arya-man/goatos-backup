# Staging Vaccination Clean-Slate Runbook

This is the canonical destructive reset and reseed procedure for vaccination
data in `goatos-stg`. Use it when staging has mixed seed/kernel obligations,
stale projections, unexplained Action Center counts, or source dates shown as
late instead of base-anchor history.

The source-date semantics in
`docs/runbooks/vaccination-seed-source-date-contract.md` are binding. A clean
database is not sufficient: the seed is complete only when every postflight
invariant below passes.

This runbook is an operational companion to
`docs/protocol-engine/migration-and-cutover.md`. That protocol-engine document
defines the canonical identity-quality classes (`accepted`, `estimated`,
`blocked_for_pc`, and `discarded`), species-owned breed vocabulary, and
idempotent backfill boundary. If this runbook and the protocol-engine contract
ever disagree, stop the seed and resolve the contract first.

## Non-Negotiable Seed Rules

1. A source date on or before the backend business date is a base schedule
   anchor. Persist it only as trusted anchor history and never materialize open
   work on or before that business date from the anchor.
2. `Pending`, blank, and `NA` are not administrations.
   - `Pending` means history is unknown/not done and the vaccination kernel is
     the only writer allowed to decide whether future work is scheduled or
     review-blocked. The seed path must not backfill synthetic due/overdue work
     from historical anchors.
   - blank/`NA` follow the reviewed source mapping; they never become invented
     completions or dates.
3. The seeder must never insert an open placeholder for `Pending` and then run
   the kernel for the same goat/rule. That creates two active writers for one
   business obligation.
4. Accepted completion evidence is authoritative even when DOB or entry date is
   missing. The generator must check accepted history before creating a
   `missing_due_date`, `missing_dob`, or `missing_entry_date` blocker.
5. Missing anchor validation is trigger-specific. `birth_age` rules require
   DOB, `post_arrival` rules require entry date, and
   `after_previous_completion` rules are anchored by accepted completion
   evidence. A missing entry date must not block a DOB-based kid rule, and a
   missing DOB must not block a post-arrival adult rule.
6. Only the published `vaccination.matrix` owns timing. Future obligations are
   generated by the kernel; the import must not hand-calculate them.
7. Repeating rules anchored by history must produce a next-cycle due date
   strictly after the backend business date. Non-repeating completed rules must
   have no active obligation for the same goat/rule, and the seed backfill must
   leave zero schedulable open work on or before the backend business date.
8. Never use partial generation for a shared environment. A timeout, failed
   goat, stuck generation run, or failed reconciliation aborts the seed.
9. Process-integrity and Calendar are projections, not seed sources. Rebuild
   both after the final obligation write and before restoring scheduled writers.

## Required Inputs

- `source-material/vgoats-seed/goats.json`
- `source-material/vgoats-seed/vaccination.json`
- `source-material/vgoats-seed/roster-name-mapping.jun26-review.csv`
- `source-material/vgoats-seed/attendance-jun-26.json`
- reviewed roster timetable JSON files
- `source-material/vgoats-seed/shed-manager-mapping.jul11-vaccination.csv`

Record SHA-256 hashes and source counts immediately before the reset. Stop when
an input changed without review, either vaccination workbook differs from the
canonical source, or the reviewed ownership mapping no longer covers every
source shed.

## Reset Sequence

1. Verify and record the active boundary before any write:
   `ravi@mesha.sg`, organization `vgoats.com`, project `goatos-stg`, folder
   `goat-os`, region `asia-south1`, Cloud SQL instance
   `goatos-stg-core-db`, tenant `00000000-0000-4000-8000-000000000001`, and
   repository `vgoats/goatos`.
2. Deploy a backend artifact containing the current migrations, seed command,
   generator, and projection commands. Record the immutable image digest.
3. Pause every staging Scheduler job that can write to Postgres, Pub/Sub, Cloud
   Tasks, or projections. Confirm no Cloud Run job execution remains active.
4. Take an on-demand Cloud SQL backup and wait for it to reach `SUCCESSFUL`.
   Record the backup identifier. Do not proceed on a pending or failed backup.
5. Through the authenticated staging Cloud SQL path, drop and recreate only the
   application `public` schema. Never copy the local database into staging.
6. Apply every migration from the deployed artifact and verify the final
   migration version.
7. Seed, in order:
   - founder/builder email grants;
   - reviewed roster/workforce;
   - reviewed strict shed manager and backup positions;
   - position duties;
   - goats, identifiers, vaccination matrix, accepted history, and kernel-owned
     open work with `seed-vaccination-real`.
8. The vaccination seed must run its embedded reconciliation and exit non-zero
   if any invariant below is violated. Do not bypass it or hand-edit its rows.
9. Recompute vaccination eligibility rollups, process-integrity projection,
   Calendar vaccination projection, and counts projection using the deployed
   artifact.
10. Run the obligation sweeper only after the seed and projections are clean,
    then recompute affected projections once more.
11. Validate DB, API, and UI evidence. Restore Scheduler jobs only after all
    checks are green. Trigger each restored critical job once and verify a
    successful execution before handoff.

## Mandatory Postflight Invariants

The seed command enforces the obligation/history subset. The operational
postflight must also record the surrounding counts.

- Source goat and identifier counts match the reviewed manifest (currently
  1,311 goats and 2,433 identifiers).
- Every source animal has a globally unique primary animal identifier. A
  secondary identifier is retained when present; a source row with no primary
  and no secondary is rejected. Source rows with missing DOB/entry anchors are
  retained as trigger-specific deferred review work and must not receive normal
  future vaccination work when the rule's own anchor is missing.
- Every source breed resolves to a species-owned `breeds.breed_id` and the
  displayed breed text. Unknown source vocabulary is a seed error, not a
  fallback to a different species or an invented default.
- Source-owned accepted completions equal the count derived from the source
  files (currently 3,389); each corresponding source obligation is completed.
- Zero seed-owned open `Pending` placeholders (`vacc-real-obl:%`).
- Zero goat/rule pairs with more than one active obligation.
- Zero active non-repeat goat/rule obligations already satisfied by accepted
  completion evidence.
- Every active repeat obligation has a due business date strictly in the future.
- Zero failed generation runs, failed goats, or stuck generation leases.
- Exactly one visible active `vaccination.matrix / V1 Real Vaccination`; no
  shared-staging test/story/dummy/local protocol or obligation data.
- Every imported vaccination shed has reviewed manager and backup ownership.
- `vaccination_eligibility_rollups` is populated and capacity buffer is 7 days.
- Process-integrity and Calendar projection build times are after the final
  obligation update; their grouped counts reconcile to canonical obligation
  counts.
- Historical source dates appear as base-anchor history. Open cards are
  explainable only from legitimate future cycles strictly after the backend
  business date or from explicit review blockers; they must not be historical
  late/overdue carry-forward from the imported anchors.
- No failed outbox/DLQ rows remain unexplained.

If any invariant fails, keep scheduled writers paused, preserve the backup and
logs, and fix/repeat the entire reset. Do not delete individual bad rows to make
the dashboard look clean.

## Runtime Prevention

- `goatos-stg-vaccination-generator` must have enough command and Cloud Run
  timeout for a full tenant pass and must fail the execution on partial work.
- `goatos-stg-process-integrity-projector` runs at least every five minutes so a
  partial or newly completed writer cannot leave an indefinitely stale green
  projection.
- A successful seed is never inferred from a UI screenshot. Preserve the source
  manifest, backup ID, deployed image digest, seed reconciliation output, DB
  invariant query output, job execution status, and final API/UI evidence.
