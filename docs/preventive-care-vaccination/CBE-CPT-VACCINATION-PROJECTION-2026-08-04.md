## Identifier Import Rule For Replacement Tags

For imports into a DB that already has stg-derived history, GoatOS must not
blindly trust the latest JSON tag as the new primary identifier. If the DB
already has an active primary tag for the goat and a later JSON row carries a
different tag:

1. Preserve the existing active primary tag.
2. Add the JSON tag as `animal_identifier_2` / alias when it belongs to the same
   deterministic goat.
3. Never create two active primary `animal_identifier_1` rows for one goat.
4. Never discard the older/fallen tag; keep it as lineage only.

This rule exists specifically because CBE/CPT animals may be double-tagged and
because some operational replacement tags, such as `901007000504379`, were
introduced during vaccination execution after the original seed packet.
