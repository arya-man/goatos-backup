## Two differences requiring resolver-aware interpretation

1. **Max shots differs by storage surface:** publishedv9 `drive_policy.max_shots_per_animal_per_drive=2`; vaccination_capacity_config stores3; compatibility max_vaccines_per_combo_session=3. Do not claim one universal confirmed effective limit from whichever row is convenient. The combined runtime precedence was not traced in this bounded data audit. Keep each source and version visible and flag integration verification.
2. **Proof scope differs:** published planv9 proof_mode=shed_level_video, while published vaccination.drive SOPv1 proof_mode=per_goat_video. Each has camera/verification constraints. This may reflect feature resolution/override behavior, not automatically a production bug. A prototype must not silently choose or merge them without the existing resolver contract.
