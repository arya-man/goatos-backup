Live E2E Finding: P0 Shed-Move Crash FIXED+VERIFIED

Certified surface: backend kernel + transaction rollback + durable outbox + handler replay
During lifecycle audit (L1), a shed-move mutation on a goat with batched obligations crashed the outbox handler with SQLSTATE 42P18. The fix (commit 10568bc2, one-line cast) landed before main push. Post-fix re-verification (L1 replay at same commit) passed on a fresh goat with identical batched state.

Pre-fix execution

Goat 003c6330-... had 5 open scheduled obligations, 2 with batch_id set. Shift to new shed: `POST /admin/goats/.../move` returned 200, event emitted, but outbox-relay returned error `obligation: update old shift batch: ERROR: could not determine data type of parameter $4 (SQLSTATE 42P18)` — handler crashed.

CheckResultEvidence
Mutation accepted (200 OK)PASSHTTP response: 200
Handler completed successfullyFAIL → FIXED (10568bc2, re-verified live below)pre-fix error=SQLSTATE 42P18; message stuck retry_scheduled — drained post-fix
Obligations re-scoped to new shedFAIL → FIXED (10568bc2, re-verified live below)pre-fix scope_id unchanged; post-fix re-run: re-scoped correctly

Root cause

File: backend/internal/obligation/adapters/postgres/repository.go, method reScopeOpenForGoatInTx, line ~3400. SQL: UPDATE obligation_batches SET context = jsonb_build_object('moved_target_id', $4, ...). Parameter $4 (goat-ID string) used only inside jsonb_build_object(...) with no explicit cast. pgx v5 cannot infer type for a parameter in an argument list, so Postgres rejects with 42P18.

Fix

Commit 10568bc2: cast $4::text. Adds regression test with a goat whose open obligation has batch_id set at shift time.

UPDATE obligation_batches SET context = jsonb_build_object('moved_target_id', $4::text, ...)
