Capabilities required by existing SOPs

This is the engine checklist. If a Slack SOP needs one of these, the builder must model it visibly and the backend must revalidate it.

Fields

  • text, number, date/time
  • select and multiselect
  • goat/RFID scan
  • shed/location picker

Media and files

  • photo and video proof
  • generic attachment
  • original/rectified proof
  • proof metadata

Rules

  • visible/required/disabled
  • block submission
  • due-date calculation
  • per-goat partial result

Workflow

  • request approval
  • operator execution
  • proof verification
  • reject/rework/accept paths

Data sources

  • active goats
  • parks/sheds
  • operators by scope
  • medicine/feed catalogs

Integration

  • Android runner
  • backend dry-run
  • audit/outbox
  • Slack/WhatsApp notification only

Conditions are created here, not hidden in code.

Use predefined rules for migrated Slack behavior, then add custom condition/action blocks for SOP-specific logic.

Add Custom Condition

This is the visual rule composer. The real implementation should persist this as DSL and re-run it on the backend.

Rule Builder

Deterministic, versioned rules. Same rules run client-side (preview) and server-side (authority). Toggle to see the preview react live.

Rule Type Library

Admins should build these as visual condition/action blocks; the preview and backend dry-run must show the same outcome.

Visibility

  • show/hide field
  • enable/disable field
  • section-level conditions

Validation

  • required if
  • range/pattern checks
  • block submission if

Workflow

  • requires supervisor
  • requires verifier
  • rework on rejection

Calculations

  • due date
  • expected count
  • task risk

Proof

  • proof required if
  • per-goat/per-batch
  • before submit/final approval

Server checks

  • live goat state
  • location active
  • idempotency/duplicates

Workflow is where you decide who does what after the task exists.

Fields collect data. Conditions decide requirements. Workflow links the human/system steps: approval, Android fill, proof gate, verification, rework, and final domain event.

Add Workflow Step

Add a node after an existing step. The full product should support drag/link editing; this preview makes the creation path explicit.
