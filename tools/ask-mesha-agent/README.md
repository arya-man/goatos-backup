# Ask Mesha coding agent

Backend for the admin-web **Ask Mesha** panel that answers leadership questions the way
Claude Code does: over the goatos codebase plus **read-only** goatos-stg data. It speaks the
same `/ceo-ai/*` contract as the Go backend, so admin-web only needs one flag:

- `CEO_AI_AGENT_URL=http://127.0.0.1:8787` → panel uses this agent.
- unset → legacy backend ceo-ai (unchanged).

## Run locally

```bash
cloud-sql-proxy --port 55432 goatos-stg:asia-south1:goatos-stg-core-db &
mkdir -p ~/.ask-mesha-agent   # state: chats.json, metrics.jsonl, uploads/, .pgenv (PG* vars for mesha_ceo_readonly)
(cd tools/ask-mesha-agent && npm ci && node server.mjs)
tools/ask-mesha-agent/start-admin-web.sh prod   # admin-web on :3300 → live stg API, flag set
```

The agent uses the machine's Claude login (or `ANTHROPIC_API_KEY`). Knobs: `ASK_MESHA_MODEL`
(default `claude-sonnet-5`), `ASK_MESHA_DEEP_MODEL` (questions starting `deep:`),
`ASK_MESHA_EFFORT` (default `low`), `ASK_MESHA_STATE_DIR`, `GOATOS_REPO`.

## Benchmark (response time)

Every answer appends a timing event to `metrics.jsonl` (first progress / first tool / first token /
total ms, tool + DB-query counts, tokens, cost). `GET http://127.0.0.1:8787/metrics` returns p50/p90.
`ASK_MESHA_BENCH_TOKEN=… node bench.mjs "question" …` drives the real `/ceo-ai/ask` path
(set the same token on the server; never set it in a deployed environment).

Speed notes: CLAUDE.md/AGENTS.md are injected into the cached system prompt
(`CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, `ENABLE_PROMPT_CACHING_1H=1`) and all chats share one
checkout, so new chats read the prefix from cache instead of re-writing it.

## Security model (read before deploying)

The agent can run shell commands. The DB role is read-only and the server passes only an
allow-listed environment to the agent, but the Bash deny-list is best-effort, not a sandbox.
A shared/server deployment must run this service as a dedicated OS user or container with no
cloud credentials, SSH keys, or deploy rights.


## Keeping the data map current

The data map is three files:

- `.agents/skills/mesha-data-map/references/views.generated.md` — generated by `gen-data-map.mjs`
  from `backend/internal/ceoai/reporting/schema_cards.go` + the live goatos-stg DB (read-only user).
- `.agents/skills/mesha-data-map/SKILL.md` and `tools/ask-mesha-agent/data-map-core.md` — hand-written
  routing (topic -> view -> columns -> date column).

### Check / regenerate by hand

```sh
make mesha-data-map-guard                         # no DB env: object-set check only, column check skipped
set -a; . /Users/raviteja/airnd/agent-local/.pgenv; set +a   # needs Cloud SQL proxy on 127.0.0.1:55432
node tools/ask-mesha-agent/gen-data-map.mjs --check           # full byte compare vs live DB
node tools/ask-mesha-agent/gen-data-map.mjs                   # rewrite views.generated.md
```

### Automated refresh

`tools/ask-mesha-agent/refresh-data-map.sh` (idempotent, lock-protected):

1. `git fetch origin main`; refreshes its own detached worktree of `origin/main` under
   `$STATE_DIR` (default `~/.local/state/mesha-data-map`), never your checkout.
2. Detects changes since the last run (state file `$STATE_DIR/last-seen`: main SHA + hash of the live
   `ceo_ai` object set): schema_cards.go edits, new/replaced `ceo_ai` views in migrations, new DB objects,
   or a stale `views.generated.md`. Nothing changed -> exit 0 quietly.
3. On change: regenerates, runs a headless `claude -p` review (tools limited to
   Read/Grep/Glob, Edit of only SKILL.md + data-map-core.md, `Bash(tools/ask-mesha-agent/ro-sql.sh:*)`
   (read-only txn, no psql `\` meta-commands) and `gen-data-map.mjs --check`) that updates SKILL.md +
   data-map-core.md and proves 5 canned leadership questions via ro-sql.sh, re-runs `--check`, refuses if any
   other file changed.
4. Commits on `chore/data-map-refresh-YYYYMMDD`, pushes that branch, `gh pr create`. It never merges and
   never pushes main; the PR body says it must land via `make land-main`.

```sh
tools/ask-mesha-agent/refresh-data-map.sh --dry-run   # detect + report, changes nothing, no state update
tools/ask-mesha-agent/refresh-data-map.sh             # real run
tail -f ~/.local/state/mesha-data-map/refresh.log
```

Env: `GOATOS_REPO` (default: this repo), `STATE_DIR`, `PGENV_FILE`
(default `/Users/raviteja/airnd/agent-local/.pgenv`), `CLAUDE_BIN`. Requires `git`, `node`, `psql`,
`gh` (authenticated), `claude` (authenticated), and the Cloud SQL proxy running.

### Schedule it

macOS (launchd, daily 07:30):

```sh
cp tools/ask-mesha-agent/schedule/sg.mesha.data-map-refresh.plist ~/Library/LaunchAgents/   # edit paths first
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/sg.mesha.data-map-refresh.plist
launchctl kickstart gui/$(id -u)/sg.mesha.data-map-refresh     # run now to test
```

Linux (systemd user timer, daily 07:30):

```sh
mkdir -p ~/.config/systemd/user
cp tools/ask-mesha-agent/schedule/mesha-data-map-refresh.{service,timer} ~/.config/systemd/user/   # edit env paths
systemctl --user daemon-reload && systemctl --user enable --now mesha-data-map-refresh.timer
systemctl --user start mesha-data-map-refresh.service   # run now to test
```
