Action types — how each one renders

Eight types exist in Workflow Type / the template tabs of Unified Workflow DB. Birth and Death use four of them — the rest belong to other workflows and are listed for completeness. Operators never see the raw token; the app shows the human label. Colour is reserved for status (done, overdue, blocked) so the type never competes with what needs attention; type is carried by glyph and label instead.

Where the content comes from

Every action, detail string, timing rule and session time is taken verbatim from the sheet. The only removal is the trailing TRIGGER_EVENT shifting steps — the birth SOP now ends at Tag the kid.

What changes from today

  • Two routes, not one toggle. /counts/birth and /counts/death replace the Birth/Death segmented control on /counts/birth-death. Each gets its own bottom-bar-reachable entry, so an operator recording a death never lands on a birth form first.
  • The module opens on work, not on a blank form. Today the screen is write-only — you submit and the record vanishes. Now the default view is the outstanding SOP actions per goat, grouped Overdue / Due today / Scheduled.
  • ＋ in the top right is the only way in to recording. "Add birth" records one child at a time; breed, mother RFID, and litter size are required.
  • Birth is per-entity, matching the engine. Birth is a multi-entity workflow, so a single delivery produces a Mother card and one card per kid, each with its own action set — the mother's 6 steps and each kid's 8 never get mixed into one checklist.
  • The birth SOP ends at "Tag the kid". The three TRIGGER_EVENT shifting steps the sheet appends (K0 → Mother, K0 → K1, K1 → K2) are gone. Birth owns birth; a move is a shifting request raised in its own module, which now needs verifier-approved video before it applies.
  • A date filter on both modules. Prev/next day plus a calendar jump, so a shed head can open yesterday and see what was due and what was completed. Past days are read-only and the list says so.
  • Status filters include Completed, not just open work — finished actions stay reachable rather than disappearing from the module.
  • A goat card is scannable in one glance: progress bar, n/total done, the single next action, and how late it is. Overdue is carried by an amber left stripe, so a shed head can triage without reading.
  • Pagination stays honest. ~20 rows per keyset page with a passive loading footer — no "Load more" button, per the mobile data-fetch rule.
  • Add birth keeps the relationship permanent. The kid receives a server-generated provisional tag. The operator scans the mother’s RFID, and the backend stores the canonical mother goat ID plus litter size on each separately entered child. Entry date is gone; date of birth is locked to today with an editable time of birth.
  • Recording a death is unchanged and still irreversible — the exit happens on submit. The two video steps are the evidence trail that follows, plus park-head sign-off once both are in.
